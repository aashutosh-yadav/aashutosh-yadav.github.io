What I'm interested in

I spend most of my time thinking about backend systems — not just making them work, but understanding why they break. Caching doesn't always help. Adding workers isn't always the answer. I want to know when and why.

Recently I've been going deeper into how databases and application servers interact under concurrency — connection pooling, queueing effects, saturation points. The gap between "it works" and "it works at scale" is where I like to dig.

Projects

URL Shortener — GitHub
Built a read-heavy backend to understand performance in practice. Got it to ~1900 req/sec at ~50ms latency. The surprising finding: adding Redis made things slower because the database wasn't the bottleneck — worker contention was. Load tested up to 500 concurrent users and mapped where the system saturates (~2500 RPS).

Learnlense — GitHub
An AI pipeline that takes a YouTube video or MP4 and produces a summary, mind map, Q&A chatbot, and more. Transcription via Whisper, LLM via LLaMA 3.3 70B through Groq. Built a fallback chain (Groq → Gemini → Ollama) so it stays up if a provider goes down. Runs in under 3 minutes on CPU only. Research paper submitted.

REST API Backend — GitHub
A complete backend with auth, CRUD, and post management. Built to get a proper understanding of JWT, OAuth2, SQLAlchemy, and how to structure a FastAPI project beyond toy examples.
